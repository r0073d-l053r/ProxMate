# Purpose

The layer between the routers and [proxmox service](/services/proxmox.md) for everything a tenant does to a guest. Every create path follows: quota check → reserve VMID → DB row `creating` → create/clone on Proxmox (waiting for the task) → isolation firewall before first boot → `stopped` → start (waited) → `running`. On failure (`settleFailedCreate`) the row is kept as `error` when its guest exists and is ours. Clones and upload restores pass their task: if it finished after all, the guest is tagged as the row's now; if it is still running, it is followed in the background (up to 6 h) and, if the row still exists with the same VMID and node, made safe by the task's `beforeTag` step (upload restore: rename, NIC rebuild, `assertOwnVolumes`, isolation, `syncRestoredGuest` — the same as an on-time restore; a failure there leaves the guest untagged) and then tagged when it completes, then the task's `afterTask` cleanup runs (upload restore: the archive). The tag only lets the row be deleted with its guest; the row stays `error`, which nothing may start. Otherwise a guest at the VMID that carries no other machine's ProxMate tag (only a template's, the duplicate source's, or none) also keeps the row as `error`, so a late clone is never left unowned. When the VMID is empty or holds another machine's guest, the row is deleted so it cannot point at whichever guest Proxmox gives that VMID next. A row that already carries a `holdReason` (over quota, foreign volumes) keeps it instead of getting the generic provisioning hold. Either way `notify({ event: 'vm.error' })` fires.[^vm]

Every guest ProxMate creates carries a Proxmox tag `proxmate-<row id>` (`guestMarker`), set in the create call (ISO, LXC) or written right after a clone, restore or snapshot rollback (`markClonedGuest`, which replaces any marker inherited from the source). Every path that changes a guest or hands over control of it goes through `requireOurGuest`; at runtime only a guest carrying the row's own tag counts as the row's.[^vm]

# Gotchas

- Placement is constrained to nodes that physically hold the ISO / LXC template (node-local storage is the #1 cause of async Proxmox failures). ISO installs and uploads are kept on amd64 nodes.[^vm]
- `planTemplateClone`: cloud-image templates always full-clone (onto `default_storage` if the node sees it); regular templates stay linked if already on the default pool, otherwise full-clone so the guest is not pinned to node-local storage (the 2026-08-01 migratability fix). If the default pool is not visible on the template node, the template's own storage is used with a warning.[^vm]
- Template deploys run on the template's node.[^vm]
- `cipassword` is never given to cloud-init (hash readable on `/dev/sr0` and `/var/lib/cloud`, pentest 2026-07-18, verified 2026-08-11). The password is stored encrypted and applied by [deploy-lock](/services/deploy-lock.md). When a password is requested, `guest-agent` is added to the snippet as a "belt"; if no snippet can be produced for it the deploy continues with a warning.[^vm]
- Only cloud-init feature ids the admin OFFERS are accepted; the always-on base applies only when on-demand snippet writing (`snippetWriteConfig`) is configured. A missing snippet for a chosen feature is a hard error.[^vm]
- Cloud-image VMs get `vga: std` so noVNC is not stuck on the serial placeholder.[^vm]
- `applyDefaultBridge` runs on every clone path before isolation. Deploy and template rebuild (`configureClonedVm`) then call `ensureNicFirewall` + `configureVmIsolation`, because cloned NICs may lack the firewall flag; `duplicateVm` re-runs only `configureVmIsolation` (fresh MAC).[^vm]
- Power-on paths (`startVm`, `restartVm`, `resumeVm`, rescue boot, `duplicateVm`) check the OWNER's access window, not the caller's, so a share-holder cannot undo a suspension. In `enterRescue`/`exitRescue` the owner check (and `requireOurGuest`) runs before the guest is stopped or its boot config rewritten, so a refusal leaves it unchanged.[^vm]
- `stopVm` writes `status: 'stopped'` regardless of whether the guest actually went down (relied on by [access-sweep](/services/access-sweep.md), which re-checks Proxmox).[^vm]
- Resize/rebuild quota is billed to the owner (a Manager resizing a shared VM is checked against the owner's caps; orphaned VM falls back to the caller). `quotaExempt` VMs stay exempt.[^vm]
- `refreshVmIps`: the LAN IP is sticky (never cleared on agent hiccup); the Tailscale IP is cleared when no longer advertised.[^vm]
- LXC: no live migration, pause, rescue, password reset, SSH-key add, or duplicate.[^vm]
