# Purpose

Lets a recipient opt out of admin broadcast (announcement) emails from the link in the email. Mounted at `/api/broadcast` outside any session auth.[^app] Unsubscribe links are generated by `POST /api/admin/broadcast` as `<appUrl>/api/broadcast/unsubscribe?token=<unsubscribeToken(userId)>`.[^admin]

# Authentication

- None at router level. The HMAC token in the `token` query string is the credential (`verifyUnsubscribeToken`); no session or CSRF cookie is involved.[^routes]
- The POST still passes the global `apiWriteLimiter` (it is under `/api`).[^app]

# Endpoints

| Method | Path | Auth | Description |
|---|---|---|---|
| GET | `/api/broadcast/unsubscribe?token=…` | HMAC token | Renders an HTML confirmation page with a field-less POST form. Never mutates. 404 HTML page if the token is invalid. |
| POST | `/api/broadcast/unsubscribe?token=…` | HMAC token | Sets the user's broadcast opt-out (`setBroadcastOptOut(userId, true)`), audits `user.broadcast_optout` (detail `via email link`), returns an HTML confirmation. Idempotent. |

# Gotchas

- Two-step on purpose: corporate mail scanners prefetch GET links, so only the explicit POST changes state.[^routes]
- The form has no fields and posts to the current URL, so the token rides the query string on both steps and no request-derived value is rendered into HTML; the user's email in the success page is HTML-escaped.[^routes]
- Responses are `text/html`, not JSON. No zod validation; the token is coerced with `String(req.query.token ?? '')`.
- Only affects announcement emails; security/account emails are not affected.

# Relationships

- Updates `broadcastOptOut` on [User](/database/user.md) via the [broadcast-optout service](/services/broadcast-optout.md).
- Sender side is `POST /api/admin/broadcast` in the [admin router](/api/admin.md); a signed-in user can also toggle the flag via `PUT /api/auth/email-preferences` in the [auth router](/api/auth.md).
- Writes [AuditLog](/database/audit-log.md) via the [audit service](/services/audit.md).
