# Bundle Update Log

## 2026-10-24
* **Update**: [VM API](/api/vm.md) and [vm service](/services/vm.md): a create that fails after answering keeps its reason for an hour (`lib/create-failures.ts`), returned by `GET /api/vms/:id` as 404 `code: 'create_failed'` to the owner or an admin; delete of a row still `creating` answers 409 while its operation is in flight; the [deploy-lock](/services/deploy-lock.md) probe interval runs from the end of the last probe.
* **Update**: Version 1.3.3: the ISO, LXC, template and upload-restore creates answer 201 with the `creating` row and finish in the background (`start*` forms and `StartedCreate` in the [vm service](/services/vm.md), `runInFlight` in `lib/in-flight.ts`; [VM](/api/vm.md) and [template](/api/template.md) APIs, [restart reconciler](/services/task-reconcile.md)); `refreshDeployState` probes at most once per 10 s per VM ([deploy-lock](/services/deploy-lock.md)); `GET /api/vms/:id` advances `ideState` through `advanceIdeState` ([ide-provision](/services/ide-provision.md)).

* **Update**: Version 1.3.1: same as 1.3.0 with corrected version numbers (the v1.3.0 tag predates the version bump).
* **Update**: Version 1.3.0: backend and frontend package versions (the Android app takes its version from the backend); roadmap Unreleased moved under Released.

## 2026-10-23
* **Update**: [Restart reconciler](/services/task-reconcile.md): `Sys.Audit` is checked per node with `/access/permissions?path=`, every node's task log must reach back to the restore's start (a rebuilt or idle node causes a hold), a task list whose total changes between pages is no proof, and a pass holds each row in flight while it settles it so an adopt meanwhile is refused.
* **Update**: [Restart reconciler](/services/task-reconcile.md): the task-list proof now needs `Sys.Audit` on every node (see [privileges](/proxmox/privileges.md); without it the reconciler always holds), reads each list in full page by page, needs the restore's own task in its node's list, allows 60 s of clock difference, and counts any task type not known to be harmless against it; adopt holds the row in flight while it runs; an upload restore never removes an archive another row still restores from.
* **Update**: [Restart reconciler](/services/task-reconcile.md): a finished upload restore is only acted on with proof from every node's task list that nothing else used the VMID since; resumed followers hold the row until settled; unknown tasks and long waits settle or notify instead of looping; adopt clears op fields and is refused while in flight.
* **Update**: [Restart reconciler](/services/task-reconcile.md) settles held rows whose late create task was being followed when the follower was lost: it resumes following, or strips and checks (removing when refused) an upload restore that finished.
* **Update**: [Restart reconciler](/services/task-reconcile.md) writes to a guest only with positive proof (the row tag, or the `proxmate-row:<id>` clone nonce); an interrupted upload restore's untagged guest is never changed; rows sharing a VMID are held, not dropped; `nextVmId` skips VMIDs that creating or error rows name.
* **Update**: [Restart reconciler](/services/task-reconcile.md): guests are claimed only with the row's tag or the clone checks (never on a task result alone), writes are conditional on the row read, unreadable tasks are retried, upload restores are kept from booting and their archive removed; new `opSourceId`/`opArchive` on [VirtualMachine](/database/virtual-machine.md).
